# 🚀 Salesforce Sprint 8 – Asynchronous Apex

## 📖 Overview

This repository contains my learning notes and engineering exercises from **Sprint 8 – Asynchronous Apex**. Throughout this sprint, I explored how Salesforce applications perform background processing using Asynchronous Apex to improve performance, scalability, and user experience.

The sprint focuses on understanding **when work should happen**, selecting the appropriate asynchronous processing mechanism, and designing reliable enterprise workflows using Salesforce best practices.

---

## 🎯 Learning Objectives

By completing this sprint, I learned to:

- Understand synchronous and asynchronous processing
- Identify tasks suitable for background execution
- Differentiate between immediate and background operations
- Implement Future Methods
- Build Queueable Apex jobs
- Process large datasets using Batch Apex
- Schedule recurring jobs using Scheduled Apex
- Design reliable asynchronous workflows
- Monitor asynchronous jobs
- Handle failures and retries effectively
- Choose the right asynchronous mechanism for different business scenarios

## ✅ Best Practices Learned

- Keep user transactions fast and lightweight.
- Move secondary tasks to background processing.
- Choose the correct asynchronous mechanism based on the business requirement.
- Use Queueable Apex for structured background jobs.
- Use Batch Apex for processing large datasets.
- Use Scheduled Apex for recurring business operations.
- Continue following Governor Limits and Bulkification principles.
- Monitor asynchronous jobs and handle failures effectively.
- Design scalable and maintainable enterprise applications.
